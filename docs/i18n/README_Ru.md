## 🚀 Что такое DayLock?

**DayLock** — это цифровой сейф с открытым исходным кодом, сервис обмена зашифрованными данными и комплекс инструментов безопасности, построенный на основе строгой архитектуры **Zero-Knowledge (нулевого разглашения)**.

Исходный текст и ключи расшифровки **никогда** не передаются на сервер или в сеть Cloudflare. Весь процесс шифрования и генерации ключей выполняется непосредственно в браузере пользователя с использованием высокопроизводительного ядра Rust WebAssembly (WASM).

**Сервер хранит только зашифрованный непрозрачный блок данных и технически не может просмотреть содержимое или восстановить ключи.**

## ✨ Ключевые возможности

- 🔐 **Архитектура Zero-Knowledge:**
  100% выполнение на стороне клиента с использованием AES-256-GCM и деривацией ключей через Argon2id на Rust/WASM.

- 🖼️ **Продвинутая стеганография:**
  Скрытие зашифрованных данных внутри изображений (PNG) и аудиофайлов (WAV/голосовые сообщения) без видимых или слышимых искажений.

- 🍯 **Ложный пароль / Защита от принуждения (Honey / Decoy Password):**
  Создание двухслойных хранилищ (правдоподобное отрицание): при принудительном разглашении пароля вводится ложный код, открывающий нейтральные данные.

- 🧩 **Разделение секрета Шамира (Shamir's Secret Sharing):**
  Разделение главного ключа на $N$ частей с возможностью восстановления только при наличии порога из $K$ частей (например, 3 из 5).

- 🚨 **Аварийная защита:**
  Мгновенное очищение оперативной памяти браузера при переключении вкладок, попытках сделать скриншот, печать или нажатии на скрытые зоны экрана.

- 🌐 **Периметральный контроль:**
  Ограничение доступа по стране посетителя (Geo-Lock), интернет-провайдеру (ASN Lock) или блокировка до определенного времени в будущем (Time-Lock).

- 💥 **Самоуничтожение после чтения (Burn-on-Read):**
  Автоматическое и окончательное удаление данных сразу после первого открытия или по истечении срока жизни (TTL).

- 💬 **Одноразовый E2E-чат:**
  Создание временных зашифрованных комнат для общения без сохранения истории и логов на сервере.

## 📖 Полное руководство пользователя

### 0. Концепция Zero-Knowledge
* **Только на вашем устройстве:** Ключи никогда не покидают браузер. Текст и файлы шифруются локально перед отправкой. Изъятие сервера или утечка базы данных раскроют лишь бесполезный зашифрованный набор символов.
* **Удаление следов:** Одноразовые записи удаляются сразу после чтения, а экстренные функции мгновенно стирают оперативно загруженные данные из памяти.
* **Важное предупреждение:** Если вы забудете главный пароль, восстановить данные будет математически невозможно. Функция сброса пароля отсутствует.

### 1. Базовое шифрование
* **Текстовое хранилище:** Безопасное хранение заметок, паролей, ключей и конфиденциальных логов с сохранением форматирования.
* **Шифрование файлов и фото:** Файлы разбиваются на блоки и шифруются в памяти браузера по алгоритму AES-256-GCM перед загрузкой.
* **Burn-on-Read:** Режим одноразовой ссылки — данные стираются из хранилища KV сразу после первой успешной расшифровки.
* **Срок жизни ссылки:** Настройка автоудаления в диапазоне от нескольких минут до нескольких дней.

### 2. Стеганография, разделение секрета и безопасный E2E
* **Стеганография в изображениях:** Внедрение зашифрованных данных в LSB-слои PNG-файлов.
  > ⚠️ **Важно:** Отправляйте изображения со скрытыми данными в мессенджерах только как **«Файл / Документ»**, чтобы сжатие не повредило внедренную информацию.
* **Стеганография в аудио:** Скрытие сообщений внутри WAV-аудиозаписей без появления шумов и искажений.
* **Разделение секрета Шамира:** Разделение ключа на $N$ частей, где для доступа требуется минимум $K$ частей.
* **Одноразовый E2E-чат:** Быстрое создание анонимных чатов для обмена зашифрованными сообщениями без сохранения следов на сервере.

### 3. Защита от принуждения и фейковые пароли (Decoy)
* **Двухслойное хранилище:** Создание двух изолированных пространств в рамках одной зашифрованной ссылки.
* **Ложный пароль:** Задание второго пароля, который открывает нейтральную информацию (список покупок, публичные заметки и т.д.).
* **Недоказуемость:** По зашифрованным данным на сервере невозможно математически доказать наличие второго (основного) слоя.

### 4. Аварийная защита и мгновенное удаление
* **Защита при смене вкладки (Tab-Switch Guard):** Мгновенная очистка расшифрованных данных из RAM при переключении вкладки или расфокусировке окна.
* **Защита от печати и скриншотов:** Размытие экрана и сброс состояния памяти при попытке сделать снимок экрана или вызвать меню печати.
* **Защита буфера обмена (Clipboard Shield):** Блокировка прямого копирования и автоматическая очистка буфера обмена через несколько секунд.
* **Скрытое удаление касанием:** Настройка комбинации нажатий в определенной зоне экрана для экстренной очистки памяти и смены интерфейса.

### 5. Периметральная защита
* **Geo & ASN Lock:** Разрешение на расшифровку только для пользователей из определенных стран или конкретных сетей (ASN).
* **Time-Locking:** Блокировка возможности расшифровки до наступления указанной даты и времени.
* **Канареечные токены (Canary Alert):** Отправка скрытого Webhook-уведомления при первой попытке перехода по ссылке.
* **Dead Man's Switch («Кнопка мертвеца»):** Автоматическое уничтожение данных, если владелец не подтверждает активность в течение заданного периода.

## 🚀 Варианты развертывания

### Вариант 1: Автоматический CLI-скрипт (Рекомендуется)

Автоматически компилирует WASM, создает хранилища KV в Cloudflare, генерирует конфигурацию и деплоит проект.

```bash
  git clone https://github.com/Chamroosh98/DayLock.git
  cd DayLock
  chmod +x setup.sh
  ./setup.sh
```

**Что делает скрипт `setup.sh`:**

1. **Авторизация:** Проверяет сессию (`wrangler login`) или API Token.
2. **Создание KV:** Создает пространства `DAYLOCK_RATE_LIMIT_KV` и `DAYLOCK_PASTE_KV`.
3. **Конфигурация:** Заполняет `wrangler.toml` полученными ID хранилищ.
4. **Сборка:** Компилирует фронтенд и подгружает собранный модуль Rust WASM.
5. **Публикация:** Разворачивает интерфейс и Worker API в сети Cloudflare Edge.

---

### Вариант 2: Ручное развертывание (Cloudflare Dashboard / Git)

1. Войдите в панель [Cloudflare Dashboard](https://dash.cloudflare.com/).
2. Перейдите в раздел **Workers & Pages**.
3. Создайте новый проект **Pages**, подключив ваш GitHub-репозиторий `DayLock`.
4. В разделе **Workers & Pages -> KV** создайте два пространства имен:
* `DAYLOCK_RATE_LIMIT_KV`
* `DAYLOCK_PASTE_KV`


5. В настройках проекта (**Settings -> Bindings**) привяжите созданные KV к переменным с аналогичными именами.
6. Нажмите **Save and Deploy**.

Для автоматического деплоя через CLI без интерактивного входа через браузер создайте токен в разделе [Cloudflare API Tokens](https://dash.cloudflare.com/profile/api-tokens) со следующими правами:

* 📜 **Workers Scripts** -> `Edit`
* 🗄️ **Workers KV Storage** -> `Edit`
